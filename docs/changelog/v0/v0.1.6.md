# jsonv-vscode v0.1.6 Changelog

**Release Date**: September 2026
**Release Type**: Patch
**Branch**: `release/0.1.6`

---

## Overview

Version 0.1.6 brings the TextMate grammar's error detection into agreement with the `@cldmv/jsonv` parser. The previous grammar missed a common typo — a forgotten comma between array or object elements — entirely, and once that detection tightened, it started flagging plenty of valid jsonv (bare references, `NaN` / `-Infinity`, numeric keys, trailing-dot decimals, `$`-prefixed keys) as errors instead. Five fix PRs, driven by tokenizing the fixture corpus straight from `@cldmv/jsonv`'s own tests, closed that gap from both directions: real mistakes are now flagged, and the language's growing feature surface no longer gets painted red. Alongside that, the deprecated `vsce` packager was replaced with `@vscode/vsce`, a `package-contents` test now guards the packaged `.vsix` file list, and the CI workflow set was synced to the current `CLDMV/.github` templates. No runtime behavior outside the grammar changed.

## 🐛 Bug Fixes

### Grammar didn't flag a missing comma between array/object values (#19, #21, #22)

`[1 2 3]` tokenized every number as valid and never raised `invalid.illegal.expected-array-separator.jsonv`; `{"a": 1 "b": 2}` scoped the second key as a string value and placed the error at the following colon instead of at the missing comma. #21 added per-element separator detection for arrays and objects; #22 fixed a regression it introduced where a multi-line first element wasn't anchored correctly, so detection now anchors to each element rather than to the opening `[` or `:`.

### Grammar flagged valid jsonv as invalid (#23, #24)

Tokenizing every non-`violations/` fixture from `@cldmv/jsonv` surfaced widespread false positives, predating and amplified by the #19 fix: bare and member references (`a: b`, `http: baseConfig.httpPort`), references inside template interpolation, `NaN` and signed `Infinity`, numeric keys (`50: 0xFAFAFA`), trailing-dot decimals and a leading `+` (`q3: 1420000.`), and `$`-prefixed unquoted keys were all painted `invalid.illegal.*`. #24 recognizes every valid jsonv value and key form the parser accepts; every fixture in the corpus now tokenizes clean.

### Three remaining grammar/parser disagreements (#25, #26)

After #24, three edge cases still disagreed with the parser: unknown string escapes (`\q`) were flagged even though the parser accepts any character after `\`; a key whose colon sits on the next line (`{a\n: 1}`) was incorrectly flagged because the colon lookahead can't see past the end of the line; and a value the parser rejects (`+Infinity`, `_1`, `- 5`) opened and closed a one-shot region at the same position, leaving the rest of the line with no scopes at all. #26 aligns the grammar with the parser on all three while keeping the `shorthand-property` violation fixture flagged.

### Grammar left some parser-rejected input unflagged (#27, #29)

Three more gaps remained: rejected values outside array elements and object values — a top-level `+Infinity`, or one inside template interpolation — went unflagged because the unrecognized-value rule only lived inside the array-element and dictionary-value-element contexts; adjacent values with no whitespace between them (`{a: /x}`, a tagged template) were merged by the one-shot value region so only the first was flagged; and a quoted key with no colon (`{ "port" }`) wasn't rejected the way the unquoted form already was. #29 flags each case and adds a regression test per case.

## 📦 Dependencies

### Migrate from the deprecated `vsce` package to `@vscode/vsce` (#30, #31)

`vsce` has been deprecated in favor of `@vscode/vsce` for some time, and the old 2.x packager could silently produce a near-empty `.vsix` — observed locally as a 2-file, 1.09 KB package with `vsce ls` listing 0 files when the checkout sat under a long path. `@vscode/vsce` now packages the extension via the `build` script (same `vsce` binary name), and a `.vscodeignore` excludes `.configs/`, `.github/`, `tests/`, the lockfile and log/vsix artifacts so the packaged extension contains exactly `package.json`, `README.md`, `LICENSE`, `language-configuration.json`, `syntaxes/**` and `icons/**`.

- Bump `minimatch` from 3.1.2 to 3.1.5 in the `npm_and_yarn` dependency group (#15).

## 🔧 CI & tooling

- Add a `package-contents` test that runs `vsce ls` through the repo's own installed `@vscode/vsce` and asserts the exact packaged file list, so a `.vscodeignore` regression fails the suite instead of silently shipping an empty or bloated extension (#18).
- Add a grammar-tokenization test suite (tokenizing the grammar against a corpus and against every valid-form fixture) and a `package.json` contributes-validation test (#18).
- Sync `.github/workflows/` with the `CLDMV/.github` v4.29.0 and v4.29.2 templates, add the bundle-size workflow, and stop it double-counting files (#17, #33).
- Remove the stray, broken monorepo ESLint config left over from the extension's extraction into its own repo — it referenced a path (`../plugins/eslint-plugin-jsonv/dist/index.mjs`) that doesn't exist here, and nothing ran it (#3, #28).

## Upgrade notes

No breaking changes — drop-in for the previous version. If you were relying on the grammar's exact error-highlighting behavior around missing commas, unusual escapes, or numeric/reference forms, expect fewer false positives and a few newly-flagged real mistakes; no `.jsonv` file that the `@cldmv/jsonv` parser accepts should highlight as invalid.
