# jsonv-vscode v0.1.1 Changelog

**Release Date**: August 2026
**Release Type**: Patch

---

## Overview

Version 0.1.1 is the first release of the extension through the CLDMV v4 release flow. The initial import (0.1.0) was never released on its own; it carried the extension itself plus a legacy `release.yml`. The extension provides language registration for `.jsonv` files (JSON5 plus the ES2015-2025 value forms), syntax highlighting through a TextMate grammar (`syntaxes/jsonv.tmLanguage.json`), `//` and `/* */` comment toggling, auto-closing pairs for braces, brackets, quotes and backticks, and light/dark language icons. It requires VS Code `^1.88.0`.

The release adopts the v4 staging-branch workflow set and fixes an npm lifecycle problem: the package's build-and-install helper was named `install`, which npm runs automatically on every `npm install` and `npm ci`, so each dependency install attempted to package the extension and install it into VS Code. No grammar, language configuration or icon files changed; extension behaviour is identical to 0.1.0.

---

## 🐛 Bug Fixes

### Rename the `install` script to `install:local` ([#4](https://github.com/CLDMV/jsonv-vscode/pull/4))

The `install` script (`npm run build` followed by `code --install-extension` on the generated `.vsix`) ran as an npm lifecycle hook on every install, including in CI. It is now `install:local` and has to be invoked explicitly with `npm run install:local`.

## 🔧 CI & tooling

- Adopt the CLDMV `@v4` staging-branch workflow set: `ci`, `publish`, `feature-pr`, `next-release`, `hotfixes-release`, `next-reset`, `hotfix-redirector`, `labeler`, `pr-title-normalizer`, `master-commit-audit`, `release-notify`, `tag-health`, `branch-retention`, `v4-bootstrap`, `cla`, `codeql`, `scorecard`, `dependency-review`, `dependabot-auto-merge`, `stale` and `welcome`, with `update-major-version-tags` refreshed. Releases now flow through the `next` to `master` release PR ([#1](https://github.com/CLDMV/jsonv-vscode/pull/1)).
- Remove the legacy v3 `release.yml` (a copy of another repository's release-PR workflow) and replace the old `ci.yml` and `publish.yml` with the v4 callers.
- Restore the CodeQL workflow under advanced setup. The extension has no analyzable source, so analysis is skipped through the `CLDMV_SKIP_CODE_SCANNING` repository variable and an empty SARIF result satisfies the code-scanning gate ([#5](https://github.com/CLDMV/jsonv-vscode/pull/5)).

## 🔧 Dependencies

- Refresh the lockfile for dev-only transitive packages (`qs` 6.14.1 to 6.15.3, `undici` 7.18.2 to 7.29.0, `tmp` 0.2.5 to 0.2.7, `hasown`, `es-object-atoms`, `side-channel` and `side-channel-list` patch updates) via a Dependabot group ([#2](https://github.com/CLDMV/jsonv-vscode/pull/2)).
